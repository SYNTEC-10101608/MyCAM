## 2. 目標

在**操作行為沒有相容性異動**的前提下，盡可能重構 MyCAM 的操作外觀，使外顯風格與底層實作都一致，並留下可持續的規範與檢查。

### 2.1 原則

1. 現有 UI 只作為操作規格的參考；操作語意不變的前提下，實作可以盡量重構。
2. 每一項改動先判斷是外觀還是行為；外觀在本議題處理，行為列入後續議題。
3. 每一類 UI 訂出建構規則：靜態時（Designer、建構子）處理哪些事、動態時（執行時）處理哪些事；能抽象共用的就共用。

### 2.2 規格限制

| 項目 | 規格 |
| --- | --- |
| 解析度 | 直式與橫式人機皆為 1920×1080、縮放 100%（96 DPI），可依此設計固定尺寸 |
| 語系 | 程式支援 zh-TW、zh-CN、en-US、ru-RU；實際維護 zh-TW、zh-CN，外觀檢查以這兩個語系為準 |
| 主題 | 淺色、現代、不失穩重；只做一套固定主題 |
| 橫 / 直式 | 依主視窗外框長寬比判斷（高 > 寬為直式），與系統顯示方向無關 |

## 4. 需求

| 編號 | 需求 |
| --- | --- |
| REQ-1 | **外顯風格一致**：所有畫面使用同一套色票、字型、尺寸、元件與編排規則 |
| REQ-2 | **底層實作一致**：同樣的外觀只有一種實作方式，集中在共用的基底與元件，不在各畫面各自處理 |
| REQ-3 | **分類必要、分類內沒有例外**：只在真的需要不同處理的地方分類；同一分類內一律依同一規則，特例須經討論並登錄 |
| REQ-4 | **操作行為不變**：使用者能做的操作、操作的順序與結果、視窗是否強制回應都與改動前相同；僅允許已核准且登錄於 [Spec.md](Spec.md#3-相容性異動) 的相容性差異，其餘列入後續議題 |
| REQ-5 | **Designer 如實呈現**：保留 Designer 排版，Designer 看到的就是執行時的樣子 |
| REQ-6 | **產品程式不留檢查用的程式**：部署的程式沒有只給檢查用的方法、屬性、旗標或分支 |
| REQ-7 | **可持續維護**：留下簡潔的專案指引與可重複執行的檢查，之後改畫面時沿用 |
| REQ-8 | **截圖如實呈現規格螢幕**：執行時的檢查與截圖在 1920×1080、縮放 100% 的螢幕上進行，不以推算或縮放代替；開發機螢幕不符時以虛擬螢幕提供 |
