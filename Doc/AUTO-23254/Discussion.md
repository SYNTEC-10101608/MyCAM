## DEC-1 工作方式

1. 每一輪依「盤點 → 草案與待決問題（附建議）→ 逐題定稿 → 施工 → 檢查」進行。
2. 整體審查由 VS Copilot 執行六輪（2026-11-21 ～ 11-22）：每輪先提交審查快照，查證後由使用者決議，再修正並回覆；
   以議題資料夾中的訊號檔（`review-reply-done.txt`、`review-log-roundN.txt`，不提交）交接。
   Round 5 時產品問題收斂，Round 6 為人工確認後的增量審查，確認沒有新缺陷。

1. 2026-11-15：**所有數值輸入一律 `DebouncedNumericUpDown`**；只顯示座標的 27 個 `TextBox` 逐一確認從不輸入後**改為標籤**。

1. 原始考量：開發機是 1366×768（實測 96 DPI），主視窗截圖以「把視窗拉大到超出螢幕」代替規格螢幕；但產品依螢幕工作區域最大化主視窗、置中並限制對話框，置中檢查在超出螢幕時只能略過，截圖也不是實際畫面。使用者要求**不以推算或縮放代替，直接提供規格螢幕**（REQ-8）。
2. **以虛擬螢幕驅動提供 1920×1080 的實體顯示裝置**，而不是改產品或模擬螢幕資訊：產品程式不變（REQ-6），Windows 回報的螢幕、工作區域與 DPI 都是真的。
3. 檢查期間暫時加入的螢幕選 **Parsec VDD**（winget `Parsec.ParsecVDD`，已簽章）：螢幕只在控制程式持續 ping 時存在，檢查期間建立、結束即移除，中斷時約一秒自動移除。VirtualDrivers VDD 的螢幕常駐、停用要系統管理員權限，不適合暫時加入，但適合當無螢幕機台的常駐主螢幕（第 8 項）。兩者安裝都需要一次系統管理員權限。
4. **不更動既有的螢幕**：已有符合規格的螢幕就直接使用（主螢幕優先，它有工作列），否則只加入虛擬副螢幕並只設定它。第一版曾把虛擬螢幕設為主螢幕並移動其他螢幕，在闔蓋、只以 AnyDesk 操作的開發機上，移動面板失敗後已寫入的配置仍被套用，筆電面板被卸離且闔蓋時無法掛回，遠端畫面全黑；以 Parsec 虛擬螢幕恢復畫面後改為此做法（REV-10）。縮放以 Windows 的顯示設定 API 固定為 100%。
5. 主視窗依產品行為**最大化**後截圖，截圖裁到螢幕可見範圍；在常駐 1920×1080 虛擬主螢幕上實測，最大化的客戶區為 1920×1009，與 Designer 在規格機台的實測值相同。`-Width` / `-Height` 的指定大小保留給議題限定的版面基準（`CompareMainLayout.ps1` 含 1366×768 等非規格大小）。螢幕無人操作的測試機（終端機，DEC-16）以 `MYCAM_UICHECK_UNATTENDED=1` 在可見桌面截圖，3D 畫面也會呈現（使用者 2026-11-26 提議）。

7. **直式不需要 1080×1920 的螢幕**（使用者 2026-11-26 指出）：`MainLayout` 只看主視窗外框的長寬比，直式在同一個 1920×1080 螢幕上把主視窗設成 1080×1880 即可。曾嘗試以 Parsec 的旋轉與自訂模式（`HKLM\SOFTWARE\Parsec\vdd\0`）提供 1080×1920，皆無法設定，因此虛擬螢幕只提供 1920×1080，移除旋轉。
8. 闔蓋、只以 AnyDesk 操作的測試機（2026-11-26 決議）：**安裝常駐的 VirtualDrivers VDD 當 1920×1080、100% 主螢幕**，它同時就是規格螢幕，登入畫面也看得到；**這台固定設定 `MYCAM_UICHECK_UNATTENDED=1`**，一般工作電腦不設定，維持隱藏桌面。
