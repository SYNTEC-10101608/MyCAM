# UI 風格統一：需求、決議與後續項目

> 議題：UI 風格盤點、優化、統一（分支 `AUTO-TBD_f_UIStyleUnify`，議題編號待補）
> 本檔記錄使用者提出的要求與討論後的決議，是本議題的唯一紀錄來源；設計內容見 [UIStyleDraft.md](UIStyleDraft.md)。
> 每次討論有新的要求或決議時，追加到對應章節，並標上日期。

## 1. 目標與原則

- 對現有 UI 做完整盤點，訂出分類規劃與風格，再全面重構。（2026-11-15）
- 現有 UI 只作為**操作規格**的參考；在操作語意不變的前提下，實作可以盡量重構。（2026-11-15）
- 除了外觀一致，**實作方式也要集中收斂**，避免不必要的實作風格分裂。（2026-11-15）
- 每一類 UI 要訂出建構規則：靜態時處理哪些事、動態時處理哪些事；能抽象共用的就共用，真的不行的再討論是否有必要分裂。（2026-11-15）

## 2. 規格限制

- 直式與橫式人機的解析度固定為 1920×1080，縮放 100%；可依此設計固定尺寸的控制項。（2026-11-15）
- 實際維護的語系只有 zh-TW、zh-CN；外觀檢查時這兩個語系顯示正常即算通過。（2026-11-15）
- 風格：淺色、現代、不失穩重。不需要主題切換，只做一套固定主題。（2026-11-15）

## 3. 決議

| 日期 | 項目 | 決議 |
| --- | --- | --- |
| 2026-11-15 | 對話框分類 | 參數編輯、互動選取、精靈、一般對話框的差別是**操作邏輯**，不是外觀。外觀上所有對話框歸為同一類，控制項與容器編排一律統一。 |
| 2026-11-15 | 數值輸入 | 所有數值輸入一律使用專案的防抖數值框（`DebouncedNumericUpDown`），現有的原生 `NumericUpDown` 與當數值用的 `TextBox` 都要改掉。 |
| 2026-11-15 | 版面建構 | 保留 Designer。Designer 看到的外觀必須如實反映執行時的樣子，不可差很多。 |
| 2026-11-15 | 字型 | 好做的話依語系切換字型。 |
| 2026-11-15 | MessageBox / 開檔對話框 | 本次不調整外觀。 |
| 2026-11-15 | 授權視窗（`FALicenseChecker`） | 本次不納入。 |
| 2026-11-15 | 舊分支 `AUTO-TBD_f_UIStyleImprove` | 外觀風格（色票、字型、尺寸）與已設計好的圖示可直接沿用；實作不參考，因為當時只做到外觀統一，沒有做到實作收斂。 |
| 2026-11-15 | 只顯示座標的欄位 | `ThreePtTransformDlg`、`CNCThreePointDlg`、`CalibrationREFDlg` 中只顯示 3D 點選座標的 27 個 `TextBox` 改為純文字標籤。**施工前要先逐一盤點語意**，確認真的從頭到尾都不會被輸入（包含執行時是否會切成可編輯），才可以改。 |
| 2026-11-15 | 語系 ID | 控制項自己使用的文字，且一個 ID 只對應一個控制項時，直接以控制項名稱當 ID，由基底類別自動套用。多個控制項共用的文字、執行時才決定的文字，仍在程式中明確取字串。 |
| 2026-11-15 | 客製語系檔相容性 | 現階段不考慮。目前沒有客戶在使用客製語系字串，語系 ID 改名造成 `Custom/Language` 舊 ID 失效可以接受。 |
| 2026-11-15 | 範圍：只做外觀，不動行為 | 本議題只做外觀統一。凡是行為差異（對話框基底的事件機制、`Show` / `ShowDialog`、主視窗的狀態與流程邏輯等）一律不動，列入後續處理。每一項改動都要先判斷是外觀還是行為。 |
| 2026-11-15 | 對話框置中 | 置中只影響視覺位置、不影響操作規格，**視為外觀**，本議題統一處理。 |
| 2026-11-15 | 置中位置 | 橫式：置中在整個主視窗。直式：置中在上半部 CAM 區域的中間，不是 CAM + CNC 整體的中間；因為 CAM 編程操作大多用不到下半部（同理，橫式在沒有切到加工模式時也不顯示 CNC 面板）。 |
| 2026-11-15 | 外框（`FormBorderStyle`） | 只影響外觀、不影響行為的部分才在本議題處理；會影響行為的要先確認。 |
| 2026-11-15 | 外框帶來的行為差異 | 盤點後確認這些行為差異應該統一，本議題一併處理：**所有對話框都不可拖曳改大小，也都不出現在工作列與 Alt+Tab。** 目前可改大小的 `ConnectDlg`、`FlyCutDlg`、`StartPointDlg`，以及會出現在工作列的 `AddPathDlg`、`ConnectDlg` 都改為一致。 |
| 2026-11-15 | 版面容器 | 對話框與嵌入式面板不使用 `TableLayoutPanel`，改用 Designer 固定座標；主視窗由 `MainLayout` 計算的動態區域維持原樣。 |
| 2026-11-15 | Designer 與衍生類別 | 外觀邏輯全部收斂在基底與共用元件。衍生的對話框只要依規範在 Designer 排版，Designer 看到的就是執行時的樣子；`InitializeComponent` 之後不應再寫任何外觀邏輯。 |
| 2026-11-15 | 共用控制項 | `MyCAM` 內自己定義的控制項都要評估移到 `CommonUI`，達到真正的統一。 |
| 2026-11-15 | 區塊標題 | 現有 UI 中語意上是「畫面區塊標題」的元素要盤點並統一處理，可參考舊分支的做法（區塊標題改為卡片標題）。 |
| 2026-11-15 | 驗收腳本 | P5 驗收要比照舊分支建立檢查腳本，驗證最終結果是否符合設計原則。 |

## 4. 後續處理項目

本議題範圍外、留待之後處理的項目。

| 日期 | 項目 | 說明 |
| --- | --- | --- |
| 2026-11-15 | 編輯工具對話框補上「取消」按鈕 | 目前部分對話框只能按 X 取消。有些 Action 可能是刻意不讓使用者按 X，補上取消鍵可能影響操作規格，需要逐一確認各 Action 的行為後再處理。 |
| 2026-11-15 | 對話框行為模式統一 | 目前三種基底（`EditDialogBase<T>`、`FormBase`、`Form`）的事件機制（預覽 / 確定 / 取消 / 重設）不一致。本議題只統一外觀，**之後做行為統一時，必須沿用本議題建立的外觀層（`DialogBase` 與共用元件），不可重新引入各自的外觀設定。** |
| 2026-11-15 | `Show` / `ShowDialog` 統一 | 自訂對話框大多以 `Show( owner )` 非強制回應開啟，`GlassDXFImportDlg`、`ConnectDlg` 以 `ShowDialog` 強制回應開啟；開啟的入口也不一致（`FormBase.Show` 覆寫、`DialogShowHelper.ShowCentered`、直接 `Form.Show`）。改變強制回應與否會影響操作，本議題不動。 |
| 2026-11-15 | 橫式人機的警報面板與日誌面板 | 橫式時兩者在訊息區上下分割（日誌 60%、警報 40%，由 `MainLayout.UpdateMessages` 計算），兩邊剩下的空間都很小。希望改成更好的處理方式，例如用一個按鈕讓兩個面板互相切換，同一時間只顯示其中一個並佔滿訊息區。屬於版面行為，本議題不動。 |
| 2026-11-15 | 主視窗行為重構 | `StartupForm.cs` 約 2000 行，混雜編輯器切換、工具列顯示 / 隱藏、CNC 面板管理、語系套用。拆分（例如抽出工具列控制）屬於行為重構，本議題不動。 |
